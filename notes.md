- Symptom: landing directly on `/messages?to=<id>` (e.g. from Requests tab avatar) → endless loading spinner.
- Root cause: StrictMode double-invoke + early-return guard; `loadedPartnerRef.current` was set BEFORE fetch; run #2 early-returned; run #1 fetch got cancelled and returned before `setLoadingMsgs(false)`.
- Fix: `src/routes/messages.tsx` — move `loadedPartnerRef.current = activePartnerId` to AFTER a successful fetch. Also trimmed `.select("*")` → explicit columns in both message queries.
- UNCOMMITTED too — alongside the /browse removal.
